# DataShield

**DataShield** - локальный русскоязычный веб-сервис для первичной самооценки обработки персональных данных в малом бизнесе по Федеральному закону № 152-ФЗ и применимым положениям GDPR.

Сервис помогает описать процессы обработки, сформировать план мероприятий, подготовить проекты документов и вести журнал инцидентов.

## Возможности

- **Анкета из 28 вопросов:** 13 вопросов о деятельности организации и 15 о принятых мерах. Варианты ответа: «Да», «Нет», «Не знаю».
- **План мероприятий:** правила подбирают применимые задачи по ответам, показывают правовые основания, приоритеты и действия. Можно менять статус, срок и пояснение.
- **Сохранение прогресса:** сведения хранятся в SQLite, а отметки по задачам сохраняются при пересчёте применимости.
- **Пять редактируемых документов DOCX:** формируются из общего профиля организации, доступны по отдельности и в ZIP-архиве.
- **Журнал инцидентов:** создание, просмотр, изменение, удаление, фильтрация и экспорт в CSV.
- **Ориентиры по уведомлениям:** при подтверждённой применимости рассчитываются сроки 24 и 72 часа по 152-ФЗ и 72 часа по GDPR с учётом отдельного времени осведомлённости контролёра.

## Технологии

- Python
- Flask 3.1.3
- SQLite
- Jinja2, HTML, CSS, JavaScript
- python-docx 1.2.0
- lxml 6.1.3

Приложение реализовано как модульный монолит с серверной генерацией HTML. Для локальной работы не нужны облачные API и отдельный сервер базы данных.

## Требования

- Python 3 с поддержкой зависимостей из `requirements.txt`
- `pip`
- Современный браузер

## Установка и запуск

Из каталога проекта, в котором находятся `app.py` и `requirements.txt`:

```bash
python -m venv .venv
```

Активируйте виртуальное окружение:

**Windows (PowerShell):**

```powershell
.\\.venv\\Scripts\\Activate.ps1
```

**Linux / macOS:**

```bash
source .venv/bin/activate
```

Установите зависимости:

```bash
python -m pip install -r requirements.txt
```

Запустите приложение:

```bash
python app.py
```

Откройте в браузере **<http://127.0.0.1:5000>**.

При первом запуске приложение автоматически создаёт каталог `instance` и базу данных `instance/datashield.db`.

По умолчанию сервер доступен только локально (`127.0.0.1`, порт `5000`). При необходимости адрес и порт задаются переменными окружения `HOST` и `PORT`. Переменная `FLASK_DEBUG=1` включает режим отладки - используйте его только при разработке.

## Как пользоваться

1. Откройте главную страницу и заполните профиль организации.
2. Перейдите в анкету и ответьте на вопросы о процессах и мерах.
3. Просмотрите сформированный план: откройте нормативные ссылки, укажите сроки и статусы задач.
4. В разделе документов просмотрите и скачайте нужные DOCX либо общий ZIP-архив.
5. При необходимости зарегистрируйте инцидент, уточните применимость уведомлений и выгрузите журнал в CSV.

Если ответ на вопрос неизвестен, оставьте «Не знаю», а не подменяйте его отрицательным ответом. Сформированные документы требуют проверки и адаптации под фактические процессы организации.

## Формируемые документы

1. Политика обработки персональных данных (`privacy_policy.docx`).
2. Согласие субъекта персональных данных на обработку (`consent.docx`).
3. Приказ о назначении ответственного (`responsible_order.docx`).
4. Реестр операций обработки персональных данных (`processing_register.docx`).
5. Порядок реагирования на инциденты (`incident_procedure.docx`).

Незаполненные реквизиты обозначаются как «Не указано». Наличие сформированного документа само по себе не подтверждает выполнение правовых требований.

## Структура проекта

```text
DataShield/
├── app.py                     # Точка входа
├── requirements.txt           # Зависимости
├── datashield/
│   ├── __init__.py            # Фабрика Flask-приложения и настройки защиты
│   ├── db.py                  # Схема и подключение SQLite
│   ├── routes.py              # HTTP-маршруты, формы и расчёт сроков
│   ├── rules.py               # Анкета и правила применимости
│   ├── documents.py           # Формирование DOCX и ZIP
│   ├── templates/             # HTML-шаблоны Jinja2
│   └── static/                # CSS и JavaScript
└── tests/
    ├── test_app.py
    ├── test_rules.py
    └── test_documents.py
```

База данных содержит четыре основные таблицы: `company`, `answers`, `requirement_progress`, `incidents`.

## Тестирование

В проекте предусмотрены **18 автоматизированных тестов**: 6 для правил, 4 для документов и 8 для приложения.

Запуск из корневого каталога:

```bash
python -m unittest discover -s tests -v
```

Проверки охватывают логику применимости, генерацию документов, обработку форм, сохранение данных и отдельные защитные механизмы. В материалах проекта также описан сквозной сценарий проверки в браузере. Автоматические тесты не являются юридической экспертизой.

## Безопасность

В локальном MVP предусмотрены:

- CSRF-защита изменяющих POST-запросов;
- параметризованные SQL-запросы;
- экранирование данных в HTML-шаблонах;
- ограничительные HTTP-заголовки, включая CSP и запрет встраивания;
- отключение кеширования ответов через `Cache-Control: no-store`;
- проверки допустимых значений в формах и базе данных.

**Важно:** текущая версия не содержит авторизации, разграничения ролей, шифрования базы и встроенного резервного копирования. Не публикуйте приложение в открытом интернете без дополнительной защиты. Доступ к локальной базе и её резервным копиям необходимо ограничивать средствами операционной системы.

## Ограничения MVP

- Один локальный профиль организации, без многопользовательского режима.
- Нет автоматического обновления нормативных правил.
- Нет автоматической отправки уведомлений Роскомнадзору или органам ЕС.
- Нет электронной подписи и автоматического юридического заключения.
- Расчёт сроков носит справочный характер; необходимость уведомления и оценку риска определяет ответственный специалист.

## Статус и развитие

**Текущий уровень готовности: TRL 4** - работающий прототип, проверенный локально. Независимая юридическая экспертиза и пилот на реальном процессе организации запланированы как следующие этапы.

План развития: проверка правил с юристом, сравнительный пилот ручного и автоматизированного выполнения задачи, затем проверка спроса на платные обновления правил и шаблонов.
